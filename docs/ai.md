# ИИ: провайдеры, что уходит в модель, MCP

Код — `packages/scan_core/lib/src/ai` и `src/analysis`. Цены и API сверены 01.11.2026.

## 1. API или MCP

Это не выбор «или-или»: два разных направления.

| | API | MCP |
|---|---|---|
| Кто кого спрашивает | Приложение отправляет запись в модель и показывает ответ | Внешний ИИ-клиент (Claude Desktop, Cursor, LM Studio…) сам читает записи через наши инструменты |
| Где работает | На телефоне, у любого пользователя | На компьютере, у тех, кто ставит MCP-клиент |
| Что решает модель | Отвечает на готовый пакет данных | Сама выбирает, какие участки и параметры смотреть |
| Этап | 3 — основной путь | 5 — для глубокого разбора и для нас: понять, какие данные модели нужны на самом деле |

Связь между ними: инструменты MCP-сервера (`list_recordings`, `get_summary`, `get_series`…)
на этапе 4 получит и модель внутри приложения через tool use — «покажи лямбду за 120–180 с».
Набор инструментов проектируем один раз (раздел 6).

## 2. Провайдеры

Пользователь выбирает провайдера, вписывает свой ключ и модель (BYOK). Ключ хранится
в Android Keystore, никуда, кроме выбранного провайдера, не уходит.

| Пресет | Протокол | Адрес | Модель | Заметки |
|---|---|---|---|---|
| Claude | Anthropic Messages | `https://api.anthropic.com` | `claude-opus-5-5` | Дешевле — `claude-sonnet-5-5`, `claude-haiku-5-5`. Из России API недоступен |
| YandexGPT | OpenAI-совместимый | `https://llm.api.cloud.yandex.net/v1` | `gpt://<ID каталога>/yandexgpt/latest` | Ключ сервисного аккаунта с ролью `ai.languageModels.user`. В режиме совместимости поддержаны только `temperature`, `max_tokens`, `stream`, `response_format`. **Проверить на живом ключе** авторизацию (`Bearer` с API-ключом) |
| OpenAI | OpenAI-совместимый | `https://api.openai.com/v1` | вписывает пользователь | |
| DeepSeek | OpenAI-совместимый | `https://api.deepseek.com/v1` | `deepseek-chat` | |
| OpenRouter | OpenAI-совместимый | `https://openrouter.ai/api/v1` | вписывает пользователь | Один ключ — модели многих компаний |
| Ollama / LM Studio | OpenAI-совместимый | `http://<IP компьютера>:11434/v1` | вписывает пользователь | Без ключа, модель на своём компьютере |

Детали запросов:

- **OpenAI-совместимый.** `POST {base}/chat/completions`, `Authorization: Bearer <ключ>`,
  сообщения `system` + `user`. Лимит токенов не отправляем: новые модели OpenAI не принимают
  `max_tokens`, а `max_completion_tokens` не знают остальные.
- **Anthropic.** `POST /v1/messages`, заголовки `x-api-key` и `anthropic-version: 2026-10-21`.
  `max_tokens: 16000`, `output_config.effort: "high"` (разбор данных — задача на внимательность) —
  только моделям, которые его принимают (`AnthropicClient.supportsEffort`): Haiku 4.5, Sonnet 4.5
  и более старые отвечают на него ошибкой 400.
  `temperature` не отправляем: на версии 2026-10-21 это ошибка 400. Для `claude-opus-5-5`,
  `claude-sonnet-5-5`, `claude-opus-5`, `claude-fable-5-1` включён серверный фолбэк
  (`fallbacks: "default"`, бета `server-side-fallback-2026-07-01`): если классификатор
  безопасности ложно сработает на автомобильные данные, сервер сам повторит запрос на
  подходящей модели. Ответ `stop_reason: "refusal"` превращается в понятную ошибку.
- Ошибки обоих протоколов сводятся к `AiException`: ключ, лимит запросов, отказ, сервер, сеть.

## 3. Что уходит в модель

Модель плохо читает тысячи точек и хорошо — сводки, поэтому `AnalysisPacket` собирает:

```json
{
  "packet_version": 1,
  "vehicle": "Lada Vesta 1.6 16V, 2019, механика",
  "duration_s": 300,
  "dtcs": [{"code": "P0171", "description": "Слишком бедная смесь, ряд 1"}],
  "pending_dtcs": [],
  "conditions": {"idle_s": 129, "driving_s": 170},
  "derived": {
    "coolant": {"start": 20, "end": 81, "max": 81, "reached_80c_after_s": 285},
    "o2_b1s1": {"crossings_per_min": {"idle": 70.9}, "sample_interval_s": 0.5, "max_detectable_per_min": 120}
  },
  "series": [
    {"key": "ltft1", "name": "Долгоср. коррекция, ряд 1", "unit": "%",
     "stats": {"all": {…}, "idle": {"median": 13.3, …}, "driving": {"median": 3.9, …}},
     "points": [[0, 1.6], [4.5, 13.5], …]}
  ]
}
```

- **Режимы.** Холостой ход — скорость < 3 км/ч и обороты < 1100. Статистика (мин, p10,
  медиана, p90, макс, среднее) отдельно для ХХ и движения: подсос воздуха виден на ХХ и
  пропадает под нагрузкой, проблема с подачей топлива — наоборот.
- **Графики.** LTTB до 60 точек на параметр: в отличие от усреднения сохраняет пики.
- **Признаки.** Прогрев (за сколько секунд до 80 °C), частота переключений лямбды с честной
  оговоркой про частоту опроса.
- **Не уходит:** VIN, время и место записи.
- **Объём:** ~20 тыс. символов, ~7 тыс. токенов на 5 минут. Растёт с числом параметров,
  а не с длительностью: точек на график не больше 60.

Оценка цены одного разбора на Claude (вход ~7 тыс. токенов, выход с рассуждением 2–4 тыс.):
Opus 5.5 ($4 / $20 за 1 млн) — около $0.07–0.11, Sonnet 5.5 ($2 / $10) — вдвое дешевле,
Haiku 5.5 ($0.10 / $0.50) — меньше цента. У остальных провайдеров — по их тарифам.

## 4. Промпт

`diagnosisSystemPrompt` в `prompts.dart`. Не меняется от запроса к запросу, поэтому у провайдеров
с кешированием префикса кешируется; данные — в сообщении пользователя. Требования к модели:
опираться только на данные, разделять «видно» и «возможная причина», не делать выводов про
системы, которых OBD-II не видит, не советовать опасных работ. Ответ из пяти частей: коротко,
что видно, причины, что проверить, срочность.

## 5. Проверка на ПК

`bin/demo.dart` делает 5 минут записи симулятором (мгновенно, без адаптера), собирает пакет
и, с `--ask`, отправляет в модель. Так подбираются промпт и модель до экрана в приложении.

Пакет без отправки:

```bash
cd packages/scan_core && dart run scan_core:demo --scenario vacuumLeak
```

Разбор моделью (PowerShell; ключ — только в переменной окружения):

```powershell
$env:AI_API_KEY = "<ключ>"; $env:AI_MODEL = "claude-opus-5-5"; dart run scan_core:demo --scenario vacuumLeak --ask
```

Для OpenAI-совместимых — ещё `AI_PROTOCOL=openai` и `AI_BASE_URL`. Вопрос владельца:
`--question "дёргается на холостых"`.

Эталонные ответы по сценариям — по ним сравниваем модели и правки промпта:

| Сценарий | Что модель должна увидеть | Ошибка модели |
|---|---|---|
| `vacuumLeak` | P0171; долгосрочная коррекция ~+13 % на ХХ и ~+4 % в движении → подсос неучтённого воздуха после ДМРВ: шланги, прокладка впуска, вентиляция картера, вакуумный усилитель | Главной причиной назвать бензонасос или форсунки (бедность была бы и под нагрузкой) |
| `thermostatStuckOpen` | P0128; ОЖ не выше ~70 °C и падает в движении → термостат открыт | Винить датчик температуры, не заметив падения в движении |
| `healthy` | Неисправностей не видно; прогрев и коррекции в норме | Найти «проблему» в норме |

## 6. MCP-сервер (этап 5)

`apps/mcp` — Dart-программа на `scan_core`, транспорт stdio. Читает папку с экспортированными
записями (`scanauto.recording` v1). Пользователь сам решает, какие записи туда положить.

| Инструмент | Что отдаёт |
|---|---|
| `list_recordings()` | id, дата, машина, длительность, коды |
| `get_summary(id)` | `AnalysisPacket` без точек графиков |
| `get_series(id, keys, from_s?, to_s?, max_points?)` | точки выбранных параметров на участке, LTTB |
| `compare(id_a, id_b, keys)` | статистика двух записей рядом: «до и после ремонта» |
| `describe_dtc(code)` | описание кода |

Подключение в Claude Desktop (пример):

```json
{
  "mcpServers": {
    "scanauto": {
      "command": "dart",
      "args": ["run", "C:/path/to/scanAuto/apps/mcp/bin/server.dart", "--dir", "C:/path/to/exports"]
    }
  }
}
```

## 7. Приватность и ответственность

- Перед первым разбором — экран: что уходит (без VIN), кому (выбранный провайдер), что ключ
  пользователя. Согласие один раз.
- Под каждым ответом — «Подсказка ИИ, не диагноз. Проверьте в сервисе перед ремонтом».
