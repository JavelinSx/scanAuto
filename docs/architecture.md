# Архитектура scanAuto

Статус: этап 0 сделан, этап 1 на старте. Версии пакетов проверены на pub.dev 01.11.2026.

Связанные документы: [ELM327 и OBD-II](obd.md) · [ИИ и MCP](ai.md) · [план этапов](mvp-plan.md)

## 1. Что делаем

Телефон подключается к адаптеру ELM327 в разъёме OBD-II, читает коды неисправностей и живые
данные двигателя, строит графики и записывает поездку. Запись в сжатом виде уходит в языковую
модель, которая объясняет владельцу, что видно в данных, что проверить и насколько это срочно.

Не делаем: запись в блоки управления (кодирование, адаптации, прошивка), протоколы
производителей (UDS, режим 22) в MVP, диагностику ABS, подушек, коробки — стандартный OBD-II
их не видит.

## 2. Ключевые решения

| # | Решение | Почему |
|---|---|---|
| D1 | На старте только Android | Самые дешёвые и массовые ELM327 — Bluetooth Classic (SPP). iOS к ним не подключается без MFi, только к BLE и Wi-Fi. Flutter оставляет путь на iOS для BLE/Wi-Fi адаптеров |
| D2 | Flutter 3.47.7 / Dart 3.13.5, как famApp | Один стек на проекты, известные пакеты (Riverpod, go_router, drift), плагины RuStore |
| D3 | Ядро — чистый Dart-пакет `scan_core` | Протокол, симулятор, запись и подготовка данных для ИИ тестируются за секунду без эмулятора. Тот же код возьмёт MCP-сервер (этап 5) |
| D4 | Только чтение: режимы 01, 03, 07, 09, 0A; режим 04 (сброс ошибок) — с подтверждением | Ошибка в записи в ЭБУ может стоить двигателя. Сброс предупреждает, что стираются стоп-кадры и готовность мониторов |
| D5 | ИИ — ключ пользователя (BYOK), сервера на старте нет | Не платим за чужие запросы, нет инфраструктуры. Ключ — в Android Keystore (`flutter_secure_storage`). Если позже будет подписка «без своего ключа» — прокси-сервер, наш ключ только на сервере, как голос в famApp |
| D6 | Два протокола ИИ: OpenAI-совместимый и Anthropic Messages | OpenAI-совместимый Chat Completions понимают OpenAI, YandexGPT, DeepSeek, OpenRouter, Ollama, LM Studio. Claude — родным API: отказы, глубина рассуждения, серверный фолбэк |
| D7 | В модель уходит пакет, а не сырая запись | Статистика отдельно для холостого хода и движения, графики, прореженные LTTB до 60 точек, посчитанные признаки. ~7 тыс. токенов на 5 минут. VIN не отправляется. Подробно — [ai.md](ai.md) |
| D8 | Симулятор адаптера и двигателя — часть ядра | Разработка без машины, детерминированные тесты, сценарии неисправностей как эталон для проверки ответов ИИ |
| D9 | Формат записи `scanauto.recording` v1 (JSON) | Экспорт, импорт и вход MCP-сервера. Хранение на телефоне — drift (SQLite) с этапа 2 |
| D10 | Транспорт за интерфейсом `ObdTransport` | Wi-Fi (TCP, `dart:io`), Bluetooth Classic, BLE и симулятор взаимозаменяемы: протокол ELM327 одинаковый |

## 4. Слои

```
apps/mobile (Flutter)                 packages/scan_core (чистый Dart)
─────────────────────                 ─────────────────────────────────
features/connect  ── выбор адаптера ─►  transport/   TcpTransport, (этап 1: BT, BLE)
features/live     ── живые данные ───►  elm327/      очередь команд, разбор ответов, ISO-TP
                     график, коды       obd/         PID (формулы J1979), коды, описания
                                        session/     Recording, LiveSampler
features/ai (эт.3) ─ разбор записи ──►  analysis/    пакет для модели, LTTB
                                        ai/          клиенты OpenAI-совм. и Anthropic, промпт
                                        simulator/   SimEngine, SimulatedElm327
apps/mcp (эт.5) ──── те же session/ + analysis/ над папкой экспортов
```

`ScanController` (Riverpod) держит подключение: создаёт транспорт, инициализирует адаптер, читает
VIN и коды, запускает `LiveSampler` и копит `Recording`. Интерфейс перерисовывается 4 раза
в секунду, а не на каждый ответ адаптера.

## 5. Разрешения Android

| Когда | Разрешение |
|---|---|
| Сейчас | `INTERNET` — Wi-Fi адаптер (TCP) и запросы к моделям |
| Сейчас | `ACCESS_NETWORK_STATE`, `CHANGE_NETWORK_STATE` — привязка сокетов к Wi-Fi адаптера (раздел 6) |
| Сейчас, Android 12+ | `BLUETOOTH_CONNECT` (спрашивается при выборе адаптера), `BLUETOOTH_SCAN` с `neverForLocation` |
| Сейчас, Android ≤ 11 | `BLUETOOTH`, `BLUETOOTH_ADMIN`. Геолокация не нужна: берём только спаренные устройства, без поиска |
| Этап 2 | `FOREGROUND_SERVICE` + `FOREGROUND_SERVICE_CONNECTED_DEVICE` — запись с выключенным экраном |

## 6. Риски

| Риск | Что делаем |
|---|---|
| Клоны ELM327 «v1.5» и «v2.1» не выполняют часть команд, медленные, теряют байты | Разбор терпит пробелы, эхо, NUL; необязательные AT-команды не валят подключение; тайм-ауты с пересинхронизацией. Этап 1 — таблица проверенных адаптеров |
| У сети Wi-Fi адаптера нет интернета, и при включённых мобильных данных Android шлёт трафик в мобильную сеть — адаптер недоступен | На время сеанса `MainActivity` запрашивает сеть Wi-Fi и привязывает к ней процесс (`bindProcessToNetwork`), при отключении снимает. Пока привязка действует, интернета у приложения нет — разбор ИИ после отключения |
| Машина не отдаёт часть PID | Опрашиваем только поддерживаемые (маска 0100/0120/…), пакет для ИИ честно говорит, чего нет |
| Модель уверенно советует ерунду | Промпт требует опираться на данные и разделять «видно» и «возможно»; на экране — дисклеймер; эталонные сценарии симулятора для проверки моделей |
| Пользователь смотрит в телефон за рулём | Запись идёт сама, разбор — после поездки. На этапе 2 — крупный режим «в дороге» без мелких элементов |
| Сброс ошибок перед продажей машины, чтобы скрыть неисправность | Не мешаем (это может любой сканер), но предупреждаем, что мониторы готовности покажут недавний сброс |
| Ключ ИИ на телефоне | Это ключ пользователя, Keystore; в логи и аналитику не пишется |
