# План этапов

Связанные документы: [архитектура](architecture.md) · [ИИ и MCP](ai.md) · [OBD](obd.md)

## Этап 0 — основа (сделано 01.11.2026)

- Репозиторий: pub workspace, `apps/mobile` (Flutter, Android, `ru.scanauto`) и `packages/scan_core`.
- Ядро: ELM327 (очередь команд, тайм-ауты с пересинхронизацией, ISO-TP), 21 PID режима 01,
  коды 03/07/0A и сброс 04, VIN, напряжение `ATRV`, `LiveSampler`, `Recording` и JSON v1.
- Симулятор адаптера и двигателя с тремя сценариями: исправный, подсос воздуха, открытый термостат.
- Пакет для ИИ (`AnalysisPacket`: режимы, LTTB, признаки), промпт, клиенты OpenAI-совместимый и Anthropic.
- Приложение: подключение к симулятору и Wi-Fi адаптеру, живые значения, график выбранного
  параметра, коды с описаниями, сброс с предупреждением.
- Wi-Fi при включённых мобильных данных: привязка сокетов к сети адаптера на время сеанса.
- Живой буфер — последние 2 часа; график ищет окно двоичным поиском.
- `effort` для Claude — только моделям, которые его принимают.
- Симулятор Wi-Fi адаптера на ПК (`dart run scan_core:sim_server`) и CI на GitHub Actions
  (формат, анализ, тесты ядра и приложения, сборка debug APK).
- Проверено: 34 теста ядра (в том числе через настоящий TCP-сокет), 5 тестов приложения
  (полный цикл через симулятор, привязка Wi-Fi), debug APK собирается.
- Не проверено: живой адаптер и машина; привязка к Wi-Fi на реальном телефоне; запросы
  к реальным провайдерам ИИ; первый прогон CI на GitHub.

  с экрана приложения, копирование промпта с данными. Подробно — [program.md](program.md).
- Часть этапа 3 этим сделана: настройки провайдера, ключ в защищённом хранилище, отправка.
  Осталось: история разборов, экран согласия, сравнение моделей на сценариях.
- Проверено: тесты ядра и приложения (вся программа на ускоренном симуляторе, отправка в ИИ
  с подменённым HTTP). Не проверено: реальная Гранта и реальный провайдер ИИ.

## Этап 1 — Bluetooth и реальные адаптеры

Сделано 07.11.2026: Bluetooth Classic своим модулем на Kotlin, разрешения Android 12+, выбор
из спаренных с подсказкой, как спарить, запоминание последнего адаптера, переподключение
с продолжением записи и программы, журнал сеанса с полным обменом и итогами этапов,
release APK на GitHub по тегу ([release.md](release.md)). Не проверено на реальном адаптере.
Осталось из этапа: BLE, таблица совместимости адаптеров.


- `BluetoothClassicTransport` (flutter_blue_classic) и `BleTransport` (flutter_blue_plus):
  у BLE-адаптеров разные UUID сервиса — таблица известных (Vgate iCar Pro, OBDLink CX, клоны FFE0).
- Разрешения Android 12+ и ≤ 11, экран выбора спаренного адаптера, запоминание последнего.
- Обработка разрыва: потеря связи → понятный экран, переподключение одной кнопкой.
- Проверка на 3–5 адаптерах и 2–3 машинах (CAN и K-Line), `docs/compatibility.md` с результатами.
- Готово, когда: клон v1.5 по Bluetooth на реальной машине показывает данные 10 минут без сбоев.

## Этап 2 — записи

- drift: записи, точки, профиль машины (марка, двигатель, год, КПП — своими словами, для ИИ).
- Запись в фоне: foreground service (connected device), wakelock, режим «в дороге» с крупными цифрами.
- Список записей, просмотр с прокруткой графика, экспорт JSON (для MCP) и CSV.
- Ускорение опроса: несколько PID в одном запросе на CAN, с откатом для клонов.
- Готово, когда: 30 минут записи с выключенным экраном, без потерь, экспорт открывается в `Recording.fromJson`.

## Этап 3 — разбор ИИ в приложении

- Настройки: пресет провайдера, ключ в `flutter_secure_storage`, модель, кнопка «Проверить ключ».
- «Разобрать» по записи или выделенному участку, поле «что беспокоит», ответ с разметкой.
- Экран согласия: что уходит и кому. История разборов в drift.
- Прогон трёх сценариев симулятора на 3–4 моделях, сравнение с эталоном из [ai.md](ai.md#5-проверка-на-пк);
  выбрать модель по умолчанию в подсказках.
- Готово, когда: на сценарии «подсос воздуха» выбранная модель называет подсос главной причиной.

## Этап 4 — диалог и инструменты

- Уточняющие вопросы по той же записи, потоковая выдача ответа.
- Tool use: модель сама запрашивает участки и параметры (`get_series`, `compare`) — те же
  инструменты, что у MCP-сервера.
