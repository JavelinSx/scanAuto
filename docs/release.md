# Релизы и журналы

## Как выходит сборка

Workflow `.github/workflows/release.yml`:

- **Тег `v*`** (например `v0.2.0`) → тесты ядра и приложения → `flutter build apk --release` →
  GitHub Release «scanAuto 0.2.0» с файлом `scanauto-0.2.0.apk`.
- **Ручной запуск** (Actions → Release → Run workflow) — тот же APK как артефакт, без релиза.
- Версия берётся из тега, номер сборки — номер запуска workflow. Версия попадает в журнал
  сеанса (`версия приложения 0.2.0`), чтобы прогон было с чем сопоставить.

Выпустить релиз:

```bash
git tag v0.2.0
```

```bash
git push origin v0.2.0
```

APK универсальный (все архитектуры), ~53 МБ. На телефоне: скачать со страницы Releases,
разрешить установку из этого источника.

## Подпись

Без секретов APK подписывается отладочным ключом, и у каждой сборки CI он свой: новая версия
не встанет поверх старой — сначала удалить прошлую (журналы при этом удалятся, перешлите их
заранее). Для нормальных обновлений нужен свой ключ — один раз:

1. Создать ключ (спросит пароли и имя; файл и пароли хранить у себя, в git и чат не класть):

   ```bash
   keytool -genkeypair -v -keystore scanauto-release.jks -alias scanauto -keyalg RSA -keysize 2048 -validity 10000
   ```

2. Получить base64 (PowerShell, кладёт в буфер обмена):

   ```powershell
   [Convert]::ToBase64String([IO.File]::ReadAllBytes("scanauto-release.jks")) | Set-Clipboard
   ```

3. GitHub → репозиторий → Settings → Secrets and variables → Actions → New repository secret:

   | Секрет | Значение |
   |---|---|
   | `ANDROID_KEYSTORE_BASE64` | строка из шага 2 |
   | `ANDROID_KEYSTORE_PASSWORD` | пароль хранилища |
   | `ANDROID_KEY_ALIAS` | `scanauto` |
   | `ANDROID_KEY_PASSWORD` | пароль ключа (часто тот же) |

Локальная релизная сборка с тем же ключом — файл `apps/mobile/android/key.properties`
(в `.gitignore`):

```
storeFile=scanauto-release.jks
storePassword=...
keyAlias=scanauto
keyPassword=...
```

`storeFile` — относительно `apps/mobile/android/`. Ключ потерять нельзя: без него обновления
не встанут поверх, только с удалением.

## Журнал сеанса

Каждое подключение пишет файл `scanauto-ГГГГММДД-ЧЧММСС.log`, в конце рядом —
`…json` с записью (формат `scanauto.recording`, VIN вычищен). Что в журнале, по тегам:

| Тег | Что |
|---|---|
| `session` | старт (адаптер, программа, профиль, версия приложения), переподключения, конец |
| `status` | шаги подключения |
| `wifi`, `bt` | привязка к сети адаптера; каким способом открылся Bluetooth-сокет |
| `elm` | весь обмен: `TX` команда, `RX` сырой ответ (`⏎` — перевод строки), `TIMEOUT`, `DROP` (опоздавший ответ), `DISCONNECTED`; версия адаптера, протокол, поддерживаемые PID |
| `dtc` | коды при подключении, сброс |
| `program` | план программы, начало каждого этапа и прогона, действия водителя |
| `stage` | итог каждого этапа сразу по окончании: длительность, цель, примечание, признаки, медианы параметров |
| `snapshot` | раз в 30 с: этап, прогон, все последние значения и сколько замеров в секунду приходит |
| `gap` | пауза в замерах от 5 с — приложение было остановлено или адаптер молчал |
| `app` | сворачивание и разворачивание приложения (`paused`, `resumed`…) |
| `service` | запустилась ли служба записи (или ошибка), уведомления, ограничение батареи, модель телефона и версия Android |
| `vaz` | разведка блока двигателя: что он ответил на запросы идентификации, режима 06 и `21 01` |
| `ai` | запрос к модели (провайдер, модель, размер), ответ и токены, ошибки. Ключ не пишется |
| `error` | обрывы и исключения со стеком |

Забрать: в приложении «Журналы сеансов» (значок на главном экране или «Журнал сеанса» после
программы) → «Поделиться» — журнал и запись уходят вместе (Telegram, почта). Или по USB:
`Android/data/ru.scanauto/files/logs`.

Запись из журнала можно разобрать на ПК тем же промптом, что в приложении, — через `Recording.fromJson`
(тот же формат, что у `bin/demo.dart`).
